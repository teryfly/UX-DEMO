# 疑难病例讨论制度闭环管理系统 · 仿真演示原型

依据 `ux-design.docx`（用户故事 / 用户旅程 / 信息架构 / 低保真原型 / 页面流程 / 字段清单）完整实现的**纯前端演示原型**。数据基于 **FHIR R4 标准**在浏览器本地（localStorage）模拟，支持完整的增删改查（CRUD），并预置了一套**符合业务逻辑、相互关联**的初始化基础数据。

> 目标：向客户演示时，通过右上角「演示角色」切换即可走通全部页面与完整跨角色业务闭环。

---

## 一、如何运行

无需任何构建工具或服务器，**直接用浏览器打开 `index.html` 即可**（推荐 Chrome / Edge）。

如需通过本地服务器访问（可选）：

```bash
cd /home/ubuntu/projects/UX-JJB/YNBLTL
python3 -m http.server 8080
# 浏览器访问 http://localhost:8080
```

- 首次打开会自动生成演示种子数据；
- 页面底部「**重置演示数据**」可随时清空缓存并重新生成；
- 顶部「帮助」按钮内含演示引导。

## 二、演示角色与完整业务闭环

右上角「演示角色」下拉可切换 5 类角色，每个角色仅可见其权限范围内的模块（严格遵循文档 IA-3.3 角色权限与导航可见性，并以「系统配置管理 › 权限配置」中每个账号的模块访问矩阵为准）。**不再设置跨角色通用首页**：切换角色或首次进入后，直接落地到该角色可访问的第一个模块首屏（个人工作台 / 讨论组织及跟踪管理 / 质量监控报表 / 系统配置管理）。

| 角色 | 可见模块 | 关键演示动作 |
|---|---|---|
| 🩺 主管医生 | 个人工作台 | 查看名下疑难病例 → 执行诊疗调整任务、反馈进度 |
| 🧑‍⚕️ 科室主任 | 讨论组织及跟踪管理、质量监控报表 | 新建讨论会议、邀请专家（含排班状态）→ 跟踪任务执行 |
| 👨‍⚕️ 会诊专家 | 讨论组织及跟踪管理（部分） | 进入研讨 → 录入讨论意见 → CA 电子签名归档 |
| 📊 医疗质量管理部门 | 质量监控报表 | 多维统计报表 → 病例全流程时间轴溯源 |
| ⚙️ 系统管理员 | 系统配置管理 | 业务规则配置、权限配置/批量、接口维护/异常排查 |

**跨角色闭环（建议演示顺序）：**

1. **科室主任**：在「讨论会议列表」对待安排病例（如*李四*）点击「安排讨论」→ 创建会议、邀请专家、发送通知。
2. **会诊专家**：在「讨论会议列表」对进行中会议（如*王五*）点击「进入研讨」→ 填写四段式标准模板 → 「CA 电子签名」。
3. **系统自动**：当全体参会专家签名完成，研讨记录**归档锁定**，会议/讨论状态自动变为「已完成」，并**自动生成诊疗调整任务**并推送待办通知。
4. **主管医生**：在「任务执行列表」收到待办 → 查看「调整详情 / 方案对比 / 执行与记录」→ 勾选医嘱、录入检查结果 → 提交办结。
5. **科室主任**：在「任务跟踪列表」查看进度、异常预警；**质管部门**在「讨论统计与溯源」对病例做时间轴溯源。

各页面的区块、弹框、状态分支（待讨论/讨论中/已完成、待执行/执行中/已完成/超时、待安排/已安排/进行中/已完成等）均按线框图与设计说明实现。

> 其中 `#/admin`（系统配置管理 L2-4）为模块入口概览页（配置模块入口 + 系统运行状态 + 配置变更日志），三个子页面通过侧边栏进入。

### 已对照设计文档逐项补全的细节

- **L2-4 系统配置管理概览页**：模块入口卡片、系统运行状态（接口连通汇总、最近配置变更摘要）、配置变更日志（最近 10 条）。
- **各角色首屏预警提示**：超时任务 / 临近截止任务 / 即将开始会议分级提示（个人工作台、讨论组织及跟踪管理概览页均按角色范围展示）。
- **筛选日期校验**：所有筛选区「起始日期不能晚于结束日期」联动约束与错误提示。
- **二次确认弹窗**：提交执行结果、保存规则、保存权限、删除权限、重新邀请专家等高风险操作均按字段清单要求弹出确认。
- **权限删除**、**Token 密钥显示/隐藏**、**接口立即检测/全部检测**实时刷新检测时间（真实操作时刻）与响应耗时、**异常接口更新配置后自动恢复正常**。
- **权限配置驱动真实访问控制**：账号「启用/停用」与模块访问矩阵直接决定该角色能否登录、能看到哪些导航模块，而不是仅作展示。
- **会议列表待处理提醒条**即「待安排 / 待确认参会 / 即将开始（30 分钟内）」三个条件筛选入口；**会议创建页**区分新建 / 安排 / 编辑模式标题。
- **更贴近真实医院规模的人员主数据**（29 名医护人员均为真实 Practitioner 记录，权限配置按人员名录生成、支持分页与新增时按名录选择）。
- **参会确认闭环**：受邀人员可在会议详情/病例详情的参会人员列表中直接「确认参会 / 拒绝参会」。
- **诊疗调整任务**：讨论结论按"治疗建议"拆分自动生成，并支持科室主任手动新建/编辑跟踪任务。

## 四、FHIR 数据建模

业务实体映射到标准 FHIR R4 资源，存储于 localStorage（`js/fhir.js` 为数据层，提供 `create/read/update/search` 及自动 `Provenance`/`AuditEvent` 操作溯源）：

| 业务概念 | FHIR 资源 |
|---|---|
| 患者 / 住院号 | `Patient` |
| 医生·专家·用户（角色/职称/科室） | `Practitioner` |
| 科室 | `Organization` |
| 住院记录（入院、床号、现病史） | `Encounter` |
| 诊断 | `Condition` |
| 检验检查报告 / 临床评分 | `Observation` |
| 医学文献 / AI 病情分析 | `DocumentReference` |
| 疑难病例识别标识（类型/依据/触发规则） | `Flag` |
| 病例讨论（中心实体） | `CaseDiscussion`（FHIR 风格自定义资源） |
| 讨论会议安排（时间/参会人/确认状态） | `Appointment` |
| 病例研讨记录 + 电子签名 | `Composition`（`attester` 即签名人/时间，`final+locked` 表示归档锁定） |
| 诊疗调整任务（状态/截止/责任人/执行节点） | `Task`（`businessStatus` 区分 待执行/执行中/已完成/超时） |
| 通知（讨论通知/参会邀请/待办/超时预警） | `Communication` |
| 操作日志 / 全流程溯源 | `AuditEvent` / `Provenance` |

业务规则、第三方接口、用户权限等系统配置存于独立的应用配置（`App.fhir.config`）。

## 五、目录结构

```
index.html              应用外壳（顶部导航 + 角色切换 + 面包屑 + 底栏）
css/styles.css          医疗临床风格设计系统
js/
  util.js               全局命名空间、日期/DOM 工具、业务枚举与样式映射
  fhir.js               FHIR 本地数据层（CRUD + 溯源）
  seed.js               初始化基础数据生成（相互关联、符合业务逻辑）
  auth.js               角色、当前用户、权限与导航可见性
  components.js         可复用 UI 组件（弹框/表格/分页/Tab/图表/步骤/时间轴…）
  domain.js             业务领域服务层（派生视图、KPI、签名/生成任务/执行等写操作）
  router.js             哈希路由 + 面包屑 + 访问控制
  app.js               引导：导航渲染、角色切换、通知抽屉、初始化
  pages/               各页面实现（workbench / discussion / meeting-create /
                       research-record / tracking / reports / admin）
```

> 说明：本原型用于演示，所有数据均在浏览器本地模拟，不与任何真实 HIS/EMR/AI/CA 系统交互。
