# 值班交接班制度闭环管理系统 — 仿真演示前端

依据《UX-值班交接班.docx》需求构建的**纯前端仿真演示程序**。所有业务数据以 **FHIR R4 标准资源**表达，通过浏览器内置的 **Mock FHIR Server** 完成增删改查（CRUD）与检索；依赖数据在缓存中按业务逻辑编造为初始化基础数据，可向客户完整演示流程与业务逻辑。

## 运行

零依赖、零构建。任选其一：

```bash
# 方式一：静态服务器（推荐）
python3 -m http.server 8099
# 浏览器打开 http://localhost:8099

# 方式二：直接双击 index.html 打开（部分浏览器对本地文件限制较多，推荐方式一）
```

右上角「身份」下拉可切换 5 种演示角色；首页按当前角色展示待处理事项、模块入口与质量指标（值班/接班医生另可在首页查询本科室已排好的值班表）。右下角「⚡ FHIR 控制台」实时显示每一次 FHIR 请求（`POST/GET/PUT/DELETE /fhir/...`），让客户直观看到数据走的是 FHIR 标准。首页「↻ 重置演示数据」可恢复初始基础数据，便于反复演示。

## 页面（对应文档信息架构 11 个页面）

- **首页** WF-L1：待处理事项、模块入口、质量指标速览（按角色呈现）
- **值班排班管理**：排班规则设置(L3-1-1) / 排班模板设置(L3-1-2) / 值班排班(L3-1-3，含冲突检查、生成值班表、提醒)
- **交接班管理**：交接班清单(L3-2-1，在院患者+待办聚合+CA 双签) / 交接班记录(L3-2-2，只读不可篡改)
- **值班质量监控**：值班执行监控(L3-3-1，到岗状态+异常处理) / 值班质量报告(L3-3-2，指标+趋势+科室对比)
- **系统管理**：系统配置管理(L3-4-1，交接模板/人员科室 FHIR 同步/系统参数) / 用户权限管理(L3-4-2，权限树)

## 核心演示动线

1. **科室负责人** → 排班规则设置 → 排班模板设置 → 值班排班（提交触发冲突检查，通过后生成值班表并发提醒）
2. **值班医生** → 交接班清单（核查重点患者、填写补充信息、CA 交班签名）
3. **接班医生** → 交接班清单（逐项核查、CA 接班签名 → 双签完成自动归档）→ 交接班记录（不可篡改）
4. **科室负责人** → 值班执行监控（到岗状态、处理超时异常）
5. **医院管理部门** → 值班质量报告（核心指标、趋势、科室对比、导出）
6. **管理员** → 系统配置管理（同步 FHIR 人员/科室数据）→ 用户权限管理

## FHIR 资源映射

| 业务对象 | FHIR 资源 |
|---|---|
| 科室 / 人员 / 资质 | Organization / Practitioner / PractitionerRole |
| 在院患者 / 诊断 / 重点标记 | Patient · Encounter / Condition / Flag |
| 待办（医嘱·会诊·危急值）/ 危急值 | Task / Observation |
| 值班排班单元 | Slot（关联 Schedule）|
| 排班规则·模板·交接模板·系统参数 | Basic |
| 交接班记录 + CA 电子签名 | Composition（status=final 不可篡改）+ Provenance（数字签名）|
| 异常通知 / 变更审计 | Communication / AuditEvent |

## 技术说明

- 纯 vanilla JS（classic scripts）+ CSS，无框架、无打包工具、无外网依赖（可离线/内网演示）。
- `assets/js/fhir.js` 为浏览器内 Mock FHIR Server：CRUD + search + 引用解析 + localStorage 持久化 + 请求控制台。
- `assets/js/seed.js` 为初始化基础数据（全部 FHIR 资源），业务逻辑自洽。
- 配色遵循文档 Ant Design 色彩规范；演示“当前时间”固定为 2026-06-20 08:00（白班）。
