# 病历管理制度闭环管理系统 — 前端演示原型

依据 `ux-desgin.docx`（用户故事 / 用户旅程 / 信息架构 / 低保真线框）实现的**纯前端仿真演示程序**。
基于 **FHIR R4 风格资源模型** 在浏览器缓存（localStorage）中模拟数据 CRUD，内置符合业务逻辑的初始化基础数据，支持**角色切换**完整演示全流程。

## 运行方式

无需任何构建或依赖，二选一：

1. **直接双击打开** `index.html`（现代浏览器，Chrome/Edge/Firefox 均可）。
2. 或启动一个静态服务器后访问：
   ```bash
   cd app && python3 -m http.server 8080
   # 浏览器打开 http://localhost:8080
   ```

> 数据缓存在浏览器 localStorage。右上角用户菜单 →「♻️ 重置演示数据」可恢复初始状态。

## 已实现页面（对应信息架构）

- **L1** 角色化首页（统计卡片 / 待办 / 通知 / 趋势 / 快捷入口，均支持点击跳转）
- **L3-1-1** 病历书写时限监控（患者两级列表、合规/归档筛选、病历详情全屏页编辑、提交归档）
- **L3-1-2** 整改任务处理（问题定位卡 + 病历编辑一体，保存自动复核）
- **L3-2-1** 整改任务追踪（科室/全院数据范围、双 Tab 详情、超时催办）
- **L3-2-2** 病历归档管理（患者病历只读 + 归档流转时间线）
- **L3-2-3** 病历质量概览（趋势折线 / 异常分布环形图 / 科室对比排行）
- **L3-2-4** 书写及时率统计（多维数据表三级分组 / 趋势 / 科室对比柱状图 / 导出）
- **L3-3-1** 书写时限配置（规则 CRUD / 变更记录）
- **L3-3-2** 质控规则配置（规则 CRUD / 模拟校验 / 版本回滚 / 通知模板设置）
- **L3-3-3** 用户权限管理（权限矩阵 / 角色模板 / 变更日志）

## 业务闭环（可在演示中完整走通）

1. **时限监控**：入院记录超时 → 首页/列表红色预警。
2. **环节质控整改**：张三 2 项待整改 → 进入「整改任务处理」编辑主诉/现病史 → 保存 → **系统自动复核通过**。
3. **提交归档 → 终末质控**：整改完成后提交归档 → 终末质控通过 → **归档成功并生成病历编号**。
4. **终末质控拦截**：赵六出院记录签字缺失 → 提交归档被**拦截** → 自动生成整改任务并通知医生 → 整改后**重新归档**。
5. **监督催办**：科室负责人/质量部门追踪超时未整改任务 → 一键**催办通知**。

## 技术结构

```
app/
├─ index.html            入口（顺序加载脚本，无打包）
├─ css/styles.css        设计系统
└─ js/
   ├─ data.js            FHIR 资源种子数据 + 缓存/持久化
   ├─ business.js        合规计算 / 质控引擎 / 归档流转 / 统计
   ├─ ui.js              组件、SVG 图表、导航与权限配置
   ├─ emr.js             病历详情/编辑器（树形模块 + 结构化内容）
   ├─ app.js             登录 / 角色切换 / 导航 / 路由
   └─ pages/*.js         各页面渲染器
```

FHIR 资源映射：`Patient/Encounter`（患者就诊）、`Composition`（病历文书）、`Task`（整改任务）、
`DetectedIssue`（质控异常）、`ActivityDefinition`（时限规则）、`PlanDefinition`（质控规则）、
`Communication`（通知）、`Provenance`（归档流转）、`AuditEvent`（审计日志）、`Organization/Practitioner`。
